# LLM Usage Report

## Tools used

The team used ChatGPT as an AI/LLM productivity tool during Assignment 2.

## How LLM tools were used

ChatGPT was used for the following activities:

1. **Assignment planning**
   The team used ChatGPT to interpret the Assignment 2 requirements, break the work into steps, and create a practical checklist of required artifacts.

2. **Repository structure planning**
   ChatGPT helped outline the expected Week 2 report structure and identify which files should be placed under `reports/week2/`.

3. **User stories drafting**
   ChatGPT assisted in drafting and organizing user stories, personas, MoSCoW priorities, requirement statuses, and the initial MVP v1 scope. The team reviewed and adapted the stories to match the KOYASH product context.

4. **MVP v0 code scaffolding**
   ChatGPT helped draft the initial FastAPI backend, React/Vite frontend, Dockerfile, and Docker Compose configuration for MVP v0. The team tested the generated code locally, fixed setup issues, and verified the smoke check manually.

5. **Debugging support**
   ChatGPT was used to understand local Docker and setup errors, including missing `docker-compose.yml`, Docker Desktop startup issues, and local endpoint access.

6. **Prototype support**
   ChatGPT assisted in preparing the Russian-language prototype structure, screen flow, UI copy, and Figma import support. The final Figma prototype was reviewed and completed manually by the team.

7. **Report drafting**
   ChatGPT assisted in drafting repository documentation, the MVP v0 report, Week 2 analysis, and this LLM usage report. The team reviewed, edited, and selected the final content before committing it.

8. **Customer communication support**
   ChatGPT helped draft a concise message to the customer requesting asynchronous review, written approval, and feedback on the user stories, MoSCoW priorities, MVP scope, Figma prototype, and public MIT repository model.

## Human review and original team effort

The team did not submit LLM output without review.

All LLM-assisted outputs were checked and adapted by the team. The team made the final decisions about:

* project scope;
* technology stack;
* user stories;
* MVP v1 priorities;
* prototype structure;
* repository commits;
* MVP v0 implementation;
* evidence screenshots;
* demo video;
* customer communication.

The MVP v0 was manually tested by the team using Docker Compose. The frontend, backend health endpoint, and sample products API were verified through a repeatable smoke check.

The Figma prototype was also manually reviewed and adjusted by the team to ensure that the flow, Russian UI text, and interaction logic match the KOYASH project.

## Limitations of LLM usage

Some LLM-generated drafts required correction or refinement. In particular:

* early prototype drafts needed to be changed from English to Russian;
* some option-selection logic needed to be clarified as single-choice or multi-choice;
* assignment-related text had to be adjusted to avoid filler and to match the actual project state;
* customer communication drafts had to be rewritten to sound natural and appropriate.

The team treated LLM output as assistance, not as a final authority.

## Final responsibility

The team is responsible for the final submitted work, including all repository artifacts, reports, prototype links, MVP v0 code, and Moodle submission materials.
