# Customer Review Summary

## Format

The customer review was conducted asynchronously via chat because a live meeting could not be scheduled before the deadline.

The customer reviewed:

* user stories;
* MoSCoW priorities;
* initial MVP v1 scope;
* Figma prototype;
* MVP v0 demo video;
* Week 2 report direction.

## Main outcome

The customer confirmed that the project direction is correct and that the current base is good. The feedback was focused on targeted improvements rather than a full redesign or scope restart.

The customer stated that the user stories are generally strong and that MoSCoW priorities and scope are in order.

## Approved or accepted decisions

The customer accepted the following decisions:

* rule-based MVP direction;
* one-question-per-screen questionnaire mechanics;
* seven-step questionnaire flow;
* budget selection by segments;
* allergens and unwanted ingredients as hard constraints;
* photo-based skin analysis as Won’t Have;
* admin panel removed from MVP scope;
* honest MVP v0 limitations.

## Requested changes

The customer requested the following changes:

1. Strengthen the KOYASH brand voice in the questionnaire.
2. Add a clear “why we ask” explanation to each questionnaire step.
3. Make “Why this product is here” the main element of product cards.
4. Make the routine structure more prominent and readable.
5. Improve the landing page so it clearly communicates trust, independence, scientific method, explainability, and technological approach.
6. Make the visual style warmer and less like a default SaaS interface.
7. Update US-01, US-02, and US-05 according to the feedback.
8. Separate decisions from hypotheses in the Week 2 analysis report.
9. Treat product data preparation as a major project risk.

## Impact on MVP v1 scope

The initial MVP v1 scope remains focused on the Must Have user stories:

* US-01;
* US-02;
* US-03;
* US-04;
* US-05;
* US-06;
* US-07.

The customer feedback does not require changing the main MVP v1 scope. Instead, it clarifies how the selected scope should be implemented and validated.

## Team response

The team will:

* update user stories to make customer feedback explicit;
* revise the Week 2 analysis report;
* document dataset preparation as a key risk;
* improve the prototype direction around brand voice, explanations, and routine clarity;
* preserve the current MVP scope unless further customer feedback changes priorities.

## Evidence

The customer provided written feedback via chat. The customer stated that the response was originally prepared from a voice message with AI assistance, but the final text was reviewed and fully validated by the customer.

The original written evidence is preserved for instructors. This file contains a sanitized summary without private customer data.
